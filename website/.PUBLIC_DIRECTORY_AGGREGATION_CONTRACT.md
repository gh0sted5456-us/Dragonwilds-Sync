# Dragonwilds Sync — Public Directory Aggregation Contract

This file is intentionally hidden from public website navigation. It is an implementation/compatibility contract for maintainers and AI coding agents working on the public Server Directory, Cloudflare Worker/D1, Desktop public World browser, WebGUI, or placard rendering.

## Goal

The public `Servers` webpage is a **combined Dragonwilds public directory**, not a Sync-only list.

It may display:

- signed Dragonwilds Sync Worlds, and
- ordinary publicly observed RuneScape: Dragonwilds servers from approved read-only public sources.

The browser must consume the single normalized Worker response. The GitHub Pages frontend must not scrape external providers, perform authoritative identity reconciliation, or hold provider/admin credentials.

Canonical flow:

```text
signed Dragonwilds Sync heartbeat ----\
                                      \
Shrug EOS session mirror --------------> Cloudflare Worker -> D1 -> identity resolver -> GET /api/v1/worlds -> website/app
                                      /
LobbySup public observations ----------/
```

## Source authority

Current external providers are the same read-only sources already used by `backend/public_worlds.py`:

- `shrug-eos-index`
- `lobbysup`

They are community observations. They are **not** represented as an official Jagex or Epic Online Services API.

Direct authenticated EOS discovery remains game/client context and is not reimplemented by the public website.

## Collection completeness

The public website must render the complete normalized set returned by Cloudflare. It must not silently cap the DOM to an arbitrary first page or first 100 records.

Cloudflare provider collection is currently configured with:

```text
PUBLIC_SOURCE_MAX_SERVERS = 500
```

per configured provider. This is a collector safety ceiling, not a website display ceiling. If provider populations grow beyond this ceiling, maintainers must review provider pagination/incremental collection instead of pretending the first subset is "all Worlds".

The API may later add explicit pagination while preserving a way for website/application consumers to traverse the whole collected set.

## Sync precedence

When a public-source observation and a Dragonwilds Sync heartbeat can be strongly identified as the same underlying World, **publish only the Dragonwilds Sync record**.

The external observation remains provenance attached to the winning Sync record and may be used to enrich non-authoritative public details, but it must not create a second placard.

A Sync record must never be replaced by an external observation merely because an external provider reports newer or different presentation data.

## Automatic match policy

Identity matching must remain conservative.

Allowed automatic strong matches:

1. exact normalized public host + exact game port, when that route maps to exactly one Sync World;
2. for sources that expose no route, exact normalized World name + exact build/version, when that combination maps to exactly one Sync World.

Provider-to-provider observations may also be collapsed when one unambiguous exact identity exists.

### Explicitly forbidden weak merge

**World name alone is not enough to merge an external observation into a Sync World.**

Do not auto-merge because of similar spelling, fuzzy name similarity, same region, same player count, same tags, or same host company.

If a match is ambiguous, keep the records separate. A false duplicate is preferable to hiding an unrelated World.

## Presentation contract

`GET /api/v1/worlds` is the canonical merged website/application response.

Sync entries should expose:

```text
directory_source = dragonwilds-sync
is_sync_world = true
source_name = Dragonwilds Sync
```

External-only entries should expose:

```text
directory_source = external-public
is_sync_world = false
source_name = <provider label>
source_id = <stable provider id>
source_world_id = <provider-scoped stable id>
```

External-only placards are limited to public fields actually supplied/derived from the public provider. They must not fabricate Sync rules, mods, verification, ownership, ratings, or administrator authority.

The website may visually distinguish external entries with a `PUBLIC SERVER` badge/source banner. A Sync World retains the richer Sync placard when promoted over a duplicate observation.

## Website view modes

The public `servers.html` page must expose both:

```text
Placards
Horizontal
```

Both views render the same normalized/deduplicated records. The view choice is presentation only and may persist locally in the browser. Horizontal view must not change filtering, identity resolution, source precedence, or public metadata.

The placard view remains the richest presentation; horizontal view is a compact layout for scanning a large public roster.

## Application-link contract

The public directory webpage publishes a machine-readable descriptor:

```text
website/directory-source.json
```

and advertises it from `servers.html` with a `dragonwilds-sync-directory` link relation.

Canonical public page:

```text
https://gh0sted5456-us.github.io/Dragonwilds-Sync/servers.html
```

Canonical read-only API:

```text
https://dragonwilds-sync-directory.dragonwilds.workers.dev/api/v1/worlds
```

The Cloudflare Worker also exposes read-only compatibility aliases:

```text
GET /worlds
GET /api/worlds
GET /manifest
GET /directory-source.json
```

These aliases do not create a second data model; they resolve to the same merged directory response.

Desktop/WebGUI/application consumers may accept the human webpage URL and resolve it to the machine-readable Public Server List feed. Pasting the webpage link must never grant publication, heartbeat, synchronization, admin, or remote-control authority.

The Desktop renderer currently exposes a dedicated `Public Server List` tab that accepts the webpage/feed URL, consumes the same merged Cloudflare response, supports Placards/Horizontal presentation, search, and read-only refresh. This display feed is separate from the fingerprint-authorized Sync Directory source used for synchronization and World linking.

## Provenance

When an external record collapses into a Sync World, preserve source provenance in fields such as:

```text
sources[]
external_observations[]
```

The published Sync record remains the presentation record.

The public API may expose aggregate duplicate counters and source-health timestamps, but never secrets.

## Storage

Cloudflare D1 owns public aggregation state:

- `worlds` — signed Sync heartbeat state.
- `heartbeat_history` — compact Sync telemetry history.
- `public_source_worlds` — normalized public observations.
- `public_source_runs` — provider refresh health.

External-source refresh uses a generation token. Do not clear the previous successful dataset merely because a provider request times out, errors, changes shape, or returns an empty/invalid result.

## Refresh behavior

The Worker refreshes configured public providers on a scheduled cadence and may also trigger a background refresh when public reads detect stale source state.

The website reads the Worker only. Do not move scheduled provider polling into GitHub Pages JavaScript.

Application display consumers should prefer the merged Worker response for this Public Server List rather than independently reproducing website deduplication rules.

## Security boundaries

External discovery is public read-only metadata. It must not introduce any path for:

- admin passwords;
- World passwords;
- WebGUI sessions;
- server/share keys;
- operator private keys;
- Cloudflare/GitHub credentials;
- arbitrary remote URLs supplied by public callers;
- remote server control.

The existing signed HMAC heartbeat path remains separate and must not be weakened to accommodate public-source ingestion.

A Public Server List webpage/feed URL is discovery configuration only. It is not equivalent to a trusted Sync endpoint, operator identity, server ownership, publication credential, or remote-admin session.

## Application parity

`backend/public_worlds.py` and the Cloudflare aggregator should preserve equivalent source IDs and matching semantics where practical.

If one side changes provider identity, normalization, or duplicate logic, review the other side in the same pass. The Desktop public browser, WebGUI, Worker, and website should not independently invent conflicting meanings for the same public server.

The application may provide a richer native public discovery path in addition to the website-backed Public Server List. Those views should converge on the same source labels and strong-match semantics instead of presenting conflicting identities.

## Maintainer verification

Before calling a public-directory change complete, verify:

1. Worker TypeScript passes strict type checking.
2. all D1 migrations are applied before Worker deployment.
3. `/health` succeeds.
4. `/api/v1/sources` exposes provider health without secrets.
5. `/api/v1/worlds` contains external public entries when sources are healthy.
6. `/worlds` resolves to the same merged public roster for application compatibility.
7. a strong external/Sync identity collision produces one Sync placard, not two.
8. a same-name-but-ambiguous collision remains separate.
9. source outage does not erase the last successful public-source dataset.
10. the GitHub Pages Server Directory renders both external and Sync records safely.
11. both Placards and Horizontal views show the same filtered record set.
12. `directory-source.json` points only at the read-only public directory API.
13. pasting the public webpage link into the Desktop Public Server List resolves and loads without granting trusted Sync/admin authority.
14. no external source is represented as official Jagex/EOS data unless an actual official contract/API is introduced later.
