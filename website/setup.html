Dragonwilds Sync does several jobs, but the setup is much simpler once you know what belongs to your computer, what belongs to a World, and which network features are optional. This guide starts with the plain-language model, then walks through Windows, Linux, Profiles, connecting, hosting, broadcasting, remote management, heartbeat telemetry, and mod loaders.

01 · Start here

The mental model

Think of Dragonwilds Sync as an organizer and traffic controller around Dragonwilds. It does not replace the game. It prepares the correct local files, remembers which World uses which configuration, performs synchronization, can expose a separate discovery endpoint, and can optionally host a remote-management interface.

PROFILELocal organization

A Profile is simply a computer-side container for a World’s files, settings, mods, save snapshot, and associations.

SYNCFile agreement

Sync compares what your Profile has with what the target World requires, then repairs or updates the managed pieces.

GAMEActual play connection

Dragonwilds itself still owns the live game session, lobby, and game-server connection.

NETWORK EXTRASDiscovery and administration

Broadcasting, heartbeat telemetry, and WebHost are separate opt-in services, not one giant exposed port.

The big distinction: “I can see a World,” “I can synchronize with a World,” “I can join the Dragonwilds session,” and “I can remotely administer the server” are four different permissions/capabilities.
02 · Windows

Initial setup on Windows

  1. Download the current Windows portable release from the Downloads page or GitHub Releases.
  2. Run Dragonwilds Sync and complete the Player Guided Setup.
  3. Select your RuneScape: Dragonwilds installation when prompted. Sync validates the layout rather than trusting a typed path blindly.
  4. Allow Player Setup to install or repair the shared client baseline when required. The normal client baseline is UE4SS plus RuneSchema.
  5. Let Sync discover local characters and saves, then enter the launcher and create or link the Profiles you actually use.
Client safety: the dedicated-server-only version.dll does not belong in the normal player runtime. Server deployment keeps server-only bootstrap files on the server side.
03 · Linux

Initial setup on Linux

The website publishes an Ubuntu Linux AppImage. Gear Lever is the recommended convenience layer because it can organize the AppImage and add a desktop entry, but Dragonwilds Sync remains portable and the AppImage can be run directly.

  1. Download the Linux AppImage from the Downloads page.
  2. Either import it into Gear Lever or mark the AppImage executable and run it directly.
  3. Point Sync to the real Steam library/game location used by that machine. If the Dragonwilds client runs through Proton/Wine, keep the Linux host path and the compatibility-prefix path conceptually separate.
  4. Let Sync identify the host/distro and validate the selected game or dedicated-server layout before enabling Profiles.

Linux distributions and Steam packaging vary. A native Steam install, Flatpak Steam install, secondary library, or dedicated server can all place files in different roots, so use Steam’s own “Browse local files”/storage view when possible instead of guessing.

04 · File locations

Finding the right file paths

The safest path is the one the platform already knows. In Steam, open the game’s Properties/Installed Files area and use the option to browse the installation. For a dedicated server installed with SteamCMD or another tool, use the install directory you explicitly chose and let Sync validate it.

05 · Profiles

What a Profile is — and is not

A Dragonwilds Sync Profile is not a website account, not a Steam account, not a public-server registration, and not a Dragonwilds lobby. It is the computer’s way of keeping one setup organized so the correct files can be activated together.

A Private World/Profile can remember things such as a save snapshot, enabled mods and configs, a preferred character, runtime associations, and the World it belongs to. That makes it practical to keep “Main World,” “Vanilla Test,” “Mod Testing,” and “Building Sandbox” side by side without manually shuffling folders.

Creating a Profile

  1. Create a new Private World/Profile or import/link an existing World.
  2. Name it for the setup it represents, not for your login identity.
  3. Associate the game/server path and preferred character where applicable.
  4. Choose the mods/configs that belong to that Profile.
  5. Launch or synchronize through the Profile so Sync can activate the correct managed state.
There is also a User Profile UI. That is presentation information such as your display name, picture, banner, and links. It is separate from the World/Profile containers that organize runtime files.
06 · Join a World

Connecting to servers

The public Worlds view can show ordinary public Dragonwilds servers as well as richer Dragonwilds Sync Worlds. A Sync-compatible World can provide the extra launcher fingerprint/metadata needed for synchronization, but the public directory itself does not grant admin access or magically join the game.

  1. Select the World you want to use.
  2. Enter any private connection or synchronization information that the owner chose not to publish.
  3. Run synchronization. Sync refreshes the manifest, resolves the character, compares runtime/mod/config state, and repairs required managed files.
  4. When preflight is clean, Sync prepares the appropriate game connection/Direct IP route and launches Dragonwilds.

Co-op is slightly different

When hosting a normal co-op game, Dragonwilds still creates the actual lobby/session. Sync can expose a separate synchronization endpoint so friends can discover and prepare the matching Profile before joining, but Sync does not replace the Dragonwilds lobby service.

07 · Host

Setting up a dedicated server

  1. Create a Server Profile or adopt an existing dedicated-server installation.
  2. Select the dedicated-server directory and let Sync inventory the current runtime before it copies, repairs, or manages anything.
  3. Confirm the server baseline and any existing UE4SS, RuneSchema, PAK, or profile-scoped mods that should belong to this World.
  4. Configure the Dragonwilds game port, the separate Sync endpoint as needed, and optional WebHost/public-directory features.
  5. Review firewall/router requirements explicitly. Sync can manage supported host firewall rules, but router publishing is never silently assumed.
  6. Start the server through the World/Profile so lifecycle, update, verification, synchronization metadata, and broadcast state stay coordinated.
Server-only loader placement: the dedicated-server version.dll belongs only on servers and should live with the server bootstrap/runtime component such as dwampi.dll. It should not be copied into the player-client runtime.
08 · Discovery

Broadcasting a World

Broadcasting is the discoverability layer. When you opt in, Dragonwilds Sync can advertise sanitized World information and a launcher fingerprint/Sync endpoint so compatible clients know that richer synchronization is available.

Public data can include the World name, status, build/version, region, public tags, rules, mods/badges, player counts, and explicitly published connection details. It must not expose WebHost administrator credentials or turn the public directory into a control plane.

09 · Remote administration

Remote login and WebHost

WebHost is the optional remote-management surface. It does not become a second independent server manager; supported actions route back through the same authoritative runtime/controller used by the desktop application.

For remote use, publish only the address that administrators need to reach, prefer HTTPS, and require explicit login. Remote actions remain permission-scoped, CSRF-protected, and auditable. The public directory and the main Dragonwilds Sync website never need your administrator password.

Keep the boundaries clean: public World discovery can be open while WebHost stays private, authenticated, or disabled entirely.
10 · Telemetry

Heartbeat and public status

A broadcasting Sync World periodically sends a signed heartbeat to the Dragonwilds Sync directory service. The Worker validates and stores the sanitized status, then the public website/application reads the normalized public API. The GitHub Pages frontend is read-only and does not receive server heartbeats directly.

A running World can reuse one runtime-start identifier for the lifetime of that server process, allowing the directory to count starts without counting every heartbeat as a new start. When heartbeats stop, the World transitions out of the active set; offline Sync Worlds can remain visible for a limited retention window before disappearing from the public directory.

Heartbeat telemetry is for status/discovery. It is not remote login, not file synchronization authority, and not a substitute for the game connection.

11 · Mod baseline

What mods and mod loaders are in the default experience?

Built-in/default loader baseline

Player Guided Setup can install or repair the shared client UE4SS + RuneSchema baseline when required. Dragonwilds Sync also understands UE4SS, RuneSchema, and PAK content as managed mod types. PAK is a content type, not another mod loader.

Default gameplay mods

Dragonwilds Sync does not need to force a gameplay-changing “mod pack” just to function. The default experience is the launcher/runtime baseline plus whichever mods a selected Profile or synchronized World actually requires. Profile enablement, tags, and load order remain profile-specific.

Optional integrations stay optional. For example, live player-position tracking can use the RSDWTools UE4SS module from RSDWDevKit when a user installs it, but Dragonwilds Sync does not bundle, install, update, or modify RSDWTools as part of the normal baseline.

Shared mod library

Mod Management keeps a shared library across Private Worlds and Server Profiles. A mod can be published to that shared library and propagated to Profiles already linked to it, while each Profile still controls whether the mod is enabled and where it sits in load order.

Simple rule: loaders make modding possible; Profiles decide which managed mods belong to a World; synchronization makes a client match the World it is joining.
12 · When something is off

Troubleshooting the first setup

  • Wrong game path: open the game through Steam and use Browse Installed Files instead of guessing the directory.
  • Linux path confusion: confirm whether Steam is native, Flatpak, or using a secondary library. Do not treat the Proton prefix as the same thing as the Steam game install.
  • Client suddenly has server files: verify that server-only version.dll was not placed in the player runtime.
  • Can see a World but cannot sync: public discovery and the private Sync endpoint/credentials are separate.
  • Can sync but cannot join: synchronization may be healthy while the Dragonwilds game port/session is unavailable.
  • Remote manager does not open: verify the WebHost address/port, HTTPS/reverse-proxy configuration, firewall, and that WebHost is actually enabled.
  • Public status looks stale: check heartbeat/broadcast configuration and outbound HTTPS before changing the website.
