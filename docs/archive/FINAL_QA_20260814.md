# Dragonwilds Sync V1 — Final QA (2026-08-14)

## Result

The V1 source, renderer, backend, Help system, screenshots, Windows builder contract, Linux builder contract, and reproducible raw-source staging workflow were refreshed and checked together.

`npm run verify` passed with an isolated test application-data directory. The gate bundled Monaco, parsed every renderer/Electron entry point, and ran all 33 retained backend regression programs through the bundled Python runtime. Identity, synchronization, security, server management, health/RPC, characters, save writeback, RSDW, Spawner, WebHost/remote administration, discovery, map, federation, World browser, and build-contract checks all passed.

The final character regression now proves a multi-style appearance change end to end: the complete cached RSDWTools hairstyle list reaches the native control, the selected preset resolves through the independently updated RSDWModel index, the preview URL changes, backup-first writeback persists the row in `Customization.CustomizationData`, and a fresh disk read rehydrates that hairstyle. The live source build exposed 12 hairstyle rows, 40 facial-hair rows, 32 head rows, and both body rows from its current RSDW cache; none are sliced by the launcher UI.

The Private World regression now snapshots two independent profiles with different UE4SS and PAK payloads, switches in both directions, preserves an outgoing live edit, and proves no cross-profile files remain. This uncovered and fixed Windows read-only cleanup for managed `mods.txt`, hotload editor files, and repeated cache replacement.

The WebHost regression now detects the WAN IP independently of UPnP. Settings displays the exact public `/servers` or `/admin/login` address separately from loopback and LAN addresses, and labels a detected-but-unmapped route as requiring a manual TCP port forward instead of claiming it is reachable.

## Raw source and builders

`npm run package:raw` stages a clean reproducible source tree at `Codex Outputs/DragonwildsSync_V1_Raw_Source`. The Windows and Linux builders both invoke the same stage as their final step and verify its required files. The Windows builder now accepts an explicit `DRAGONWILDS_SYNC_PYTHON` path before falling back to the machine Python launcher, which makes CI and controlled toolchains deterministic.

The staged raw folder excludes dependency caches and generated release/build folders while retaining source, resources, documentation, packaging definitions, scripts, manifests, and license material. `RAW_SOURCE_CONTENTS.md` describes the result.

## Production package boundary

The Windows build program passed PowerShell parse checks and its automated build-contract test. A fresh NSIS/Portable artifact was not produced during this final pass because the current sandbox could not reach PyPI to install the pinned PyInstaller toolchain, and privileged execution was unavailable after the active Codex usage allowance was exhausted. This is an environment/toolchain block, not a passed package result; no installer is labeled current or verified.

To complete the binary stage on a normal connected Windows machine, run `build.bat`. The program verifies pinned Python/Node dependencies, reruns the full gate, freezes and smoke-tests the JSON-RPC service, creates NSIS and Portable packages, inspects packaged resources, and then restages the raw source folder.

Native Linux AppImage, tar.gz, and Flatpak artifacts must still be produced and runtime-tested on Linux or through the included Ubuntu workflow. Windows verifies their source/build contracts only.

## External/live-service boundaries

- No destructive character edit, character deletion, real review submission, firewall change, port forward, SteamCMD server installation, game launch, or remote upload was performed against user data during this pass.
- Character appearance writeback was proven against an isolated synthetic Dragonwilds save, not the user's real character file.
- Public discovery and self-hosted directory behavior are implemented and regression-tested, but real Internet population still depends on legitimate upstream sessions, reachable endpoints, and operator-provided directory URLs.
- A World is promoted to Sync-enabled only after its direct protocol/fingerprint evidence verifies; country or hosting-provider metadata never substitutes for that proof.
