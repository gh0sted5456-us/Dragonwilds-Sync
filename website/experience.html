Experience · Start here

Understand the launcher
before you touch a setting.

Dragonwilds Sync is easiest to use when you understand three ideas: a Profile organizes local files and settings, a World describes a playable Dragonwilds environment, and synchronization makes your computer match the World you are joining or hosting.

01 · Initial setup

Windows and Linux follow the same basic flow.

On first launch, Dragonwilds Sync asks where Dragonwilds lives, validates the installation, prepares the shared runtime baseline when needed, discovers local saves/characters, and then opens the launcher. The goal is to identify the real game files once and let profiles handle the organization afterward.

1Install / open Sync
2Choose Dragonwilds
3Validate runtime
4Discover saves
5Create or join a World

Windows

  1. Download the current Windows release from the Downloads page or GitHub Releases.
  2. Run Dragonwilds Sync and complete Player Guided Setup.
  3. When asked for the game installation, choose the Dragonwilds folder containing the game's executable/content rather than a shortcut.
  4. Allow Sync to validate or repair the shared UE4SS + RuneSchema client baseline when required.
  5. If Windows Firewall asks about a local service, only allow the network scope you actually intend to use.

Linux

  1. Download the AppImage. Gear Lever is recommended for desktop integration, but it is optional.
  2. Make the AppImage executable if your desktop does not do that automatically, then launch it.
  3. Select the native dedicated-server path when hosting natively on Linux. For a game client running through Steam/Proton, point Sync at the actual Dragonwilds prefix/install rather than the launcher shortcut.
  4. Keep Proton/Wine compatibility separate from native server behavior; Sync identifies the host platform and manages the profile around the path you select.
Important: the dedicated-server-only version.dll is not part of the normal player runtime. Player setup must not place it into the game client. Server-side runtime files belong with the dedicated server and its server components.
02 · Paths

Finding the right folders.

The safest rule is simple: use the actual installation folder, not a desktop shortcut and not a random Mods folder you created previously.

Steam on WindowsSteam → Library → RuneScape: Dragonwilds → Properties → Installed Files → Browse.
Steam on LinuxSteam → Properties → Installed Files → Browse. Proton prefixes normally live beneath your Steam library's steamapps/compatdata area.
Dedicated serverSelect the server installation that actually runs the Dragonwilds dedicated-server executable. Keep client and server installations separate when they are separate machines or runtimes.
Sync dataLet Dragonwilds Sync own its application/config/profile storage. Do not manually merge profile folders unless you are deliberately recovering data from a backup.
03 · Profiles

A Profile is just organization.

A Profile is not a Dragonwilds account, Steam identity, server login, character, or online subscription. It is simply your computer's way of grouping the files and preferences that belong together.

Think of it like a labeled drawer: “Main World,” “Vanilla Test,” “Mod Testing,” or “Building Sandbox.” Each drawer can remember a different save snapshot, enabled mods/configs, preferred character, connection information, and launch state.

  1. Create or import a Profile.
  2. Give it a clear name based on what you use it for.
  3. Link the World/server or local save it belongs to.
  4. Choose the mods and settings for that Profile.
  5. Launch through the Profile so Sync can hydrate the correct state before Dragonwilds starts.
Changing Profiles changes which organized set of files/settings Sync prepares. It does not magically create another Steam account, another server, or another Dragonwilds character.
04 · Joining

Connecting to a server: discovery first, synchronization second, game connection last.

The public directory is a discovery layer; it is not a gameplay relay. A server can advertise safe public information so you can find it. When you choose a compatible World, Sync contacts that World's Sync endpoint, verifies its identity, compares your local runtime/mod/config state, and prepares the client before Dragonwilds joins the game server.

  1. Open Worlds or the public server directory.
  2. Select a compatible World. Public discovery may provide the World name, fingerprint, region, build, tags, and public connection metadata.
  3. Enter private information such as a password/passcode only when the World requires it; that information is not supposed to be broadcast publicly.
  4. Run synchronization. Sync refreshes the manifest and compares required runtime, mods, and configuration.
  5. Once the Profile is current, Launch performs the preflight and prepares Direct IP/game launch.

For normal Dragonwilds co-op, Sync can advertise the launcher/sync endpoint so friends can prepare their clients, but Dragonwilds itself still creates the actual co-op lobby/session.

05 · Hosting

Setting up and broadcasting a server.

A hosted World has two jobs: run Dragonwilds and publish enough Sync information for compatible clients to prepare themselves. Those jobs are related, but they are not the same network service.

  1. Create or import a Server/World Profile.
  2. Point it at the dedicated-server installation and save data.
  3. Set the game port and the separate Sync/management ports required by your configuration.
  4. Choose visibility: private/direct, directory-listed, or another supported publishing mode.
  5. Start the hosted World. Sync manages the launcher-side lifecycle and the server process as separate concerns.
  6. If you publish publicly, configure a Directory Source and publisher token where required.

Broadcasting sends sanitized metadata and a launcher fingerprint. It does not mean the directory owns your server or carries the gameplay traffic.

06 · Remote access

WebHost, remote login, and heartbeats.

WebHost is Dragonwilds Sync's integrated HTTP service. It can expose public-safe directory/API routes and, when you enable it, authenticated server administration. It is intentionally separate from starting or stopping a hosted World.

Remote login

Server users are created on the desktop host and assigned to one hosted World with explicit permissions. Remote login can be disabled without stopping the website, directory, API, or game server. The public website never needs to store the administrator password.

Publishing it

For Internet access you can use direct WAN/DNS with the correct firewall/router/reverse-proxy configuration, or an optional Cloudflare Quick Tunnel for temporary evaluation. Stable production hosting should use a durable DNS/HTTPS route you control.

Heartbeat

A heartbeat is a small repeating “I am still here” message sent to an enabled directory source. Current documentation uses a five-minute expiry by default while active launchers republish about every 60 seconds. If heartbeats stop, the directory lets the listing age out rather than pretending the server is still online.

The directory is not an admin credential broker, mod mirror, or gameplay relay. Public discovery, synchronization, game traffic, and authenticated administration are deliberately separate boundaries.
07 · Default experience

What Sync manages by default — and what it does not.

ComponentDefault roleWhat to know
UE4SSManaged runtime / mod-loader prerequisiteSync can install or update the shared UE4SS baseline for supported client/server profiles.
RuneSchemaManaged Dragonwilds data-mod prerequisiteSync manages the RuneSchema core independently. RuneSchema is not treated as a normal dynamic UE4SS mod entry.
version.dllDedicated-server-only runtime fileDo not place it in the normal player runtime. It belongs to supported server-side installation/layout only.
RSDWToolsOptional external telemetry moduleNot bundled, installed, updated, or modified by Dragonwilds Sync. Features such as live player-position telemetry can use it when the user installs it separately.
Gameplay modsProfile/server-specific contentDragonwilds Sync does not silently force a collection of gameplay-changing mods into every Profile. Mods are added to the shared library and enabled per Profile/World as required.

In other words, the default experience provides the launcher and the runtime foundation needed to synchronize compatible Worlds. A World's actual gameplay mod list remains part of that World's/Profile's requirements. When you connect, the authoritative World manifest tells Sync what must be compared or synchronized.

08 · Plain English

Common terms without the networking jargon.

ProfileA local organizational container for files, settings, mods, save state, and preferred connection context.
WorldA playable Dragonwilds environment/profile. It may be local, co-op, dedicated, private, or public.
Sync endpointThe launcher service clients contact to compare identity/manifests and prepare before joining.
Broadcast / DirectoryOpt-in discovery metadata that helps other launchers find a World. It does not carry gameplay.
HeartbeatA periodic status publication that keeps a directory listing fresh.
WebHostThe integrated website/API/remote-management service that can remain running independently of a game server.
Remote loginAn authenticated, permission-scoped WebHost session created from desktop-managed server users.
ManifestThe list/fingerprint of files, mods, runtimes, and configuration a compatible client should compare.
World BuilderA browser tool for creating a portable World Draft; the desktop app finishes local runtime/server setup before first launch.
